# VideoCompass AI 2.2 — практическое задание №4

Отдельная учебная версия сервиса анализа публичных YouTube-видео. Проект занятия №3 не изменён и продолжает работать независимо.

- Основной сайт: https://videocompass.vercel.app
- Резервный адрес: https://video-compass-ai-4216-lesson4.vercel.app
- GitHub: https://github.com/Konstantin1043/video-compass-ai-4216-lesson4

Сервис получает доступные субтитры через Apify и создаёт структурированный разбор через Google Gemini на русском, английском или латышском языке. Один новый внешний анализ расходует один внутренний кредит; сохранённая история и результат из 24-часового кэша открываются без нового обращения к Apify и Gemini и без списания кредита.

## Выполнено по заданию

- регистрация и вход через Supabase Auth;
- 10 бесплатных анализов в день по часовому поясу `Europe/Riga`;
- публикация отдельного проекта на Vercel;
- автоматические тесты основных пользовательских, серверных и защитных сценариев;
- анализ безопасности сервиса;
- адаптивная версия для компьютера, планшета и телефона.

## Возможности версии 2.2

- устойчивые этапы «транскрипт → Gemini → сохранение» с продолжением после перезагрузки;
- идемпотентные задания, блокировка параллельной обработки и возврат кредита при ошибке или зависании;
- общий кэш публичных роликов на 24 часа без повторного списания;
- до 30 обычных анализов на 30 дней, избранные хранятся до ручного удаления;
- история, поиск по всем языкам, избранное, удаление и повторное открытие результатов;
- проверяемый структурированный результат: 8 разделов, оценка, 5–7 пунктов резюме, главы и 3 вопроса для самопроверки;
- вкладки «Анализ», «Транскрипт» и «Главы», поиск по транскрипту и кликабельные тайм-коды;
- демонстрационный результат без регистрации;
- экспорт в TXT, Markdown и PDF с поддержкой RU/EN/LV;
- раскрытые по умолчанию разделы анализа, адаптивное превью ролика и выпадающий выбор языка;
- Cloudflare Turnstile, проверка Origin, ограничения запросов и защитные лимиты внешних анализов;
- показ пароля, полное удаление аккаунта после повторной проверки пароля;
- политика конфиденциальности на трёх языках.

Основная модель — `gemini-3.5-flash-lite`, резервная — `gemini-3.1-flash-lite`. Модель `gemini-3.7-flash` не используется.

## Структура проекта

```text
index.html, styles.css, app-v21.js        интерфейс 2.2
assets/                                   адаптивная иллюстрация
api/analysis/[action].js                  маршруты start/step/status/history
lib/analysis-api/                         этапы, кэш, история и кредиты
api/export/pdf.js                         PDF-экспорт
api/auth/, api/account/                   аккаунт и сессия
api/cron/cleanup.js                       ежедневная очистка
lib/                                      Apify, Gemini, Supabase и защита
supabase/migrations/                      SQL-схема, функции и RLS
test/                                     автоматические тесты
```

Старый `POST /api/analyze` сохранён для совместимости. В проекте также оставлена серверная совместимость с ранее созданными публичными ссылками, но в текущем интерфейсе функция их создания отсутствует.

## Настройка Supabase

Последовательно выполнить миграции:

1. `supabase/migrations/202608270001_auth_and_daily_credits.sql`;
2. `supabase/migrations/202608280001_video_compass_21.sql`;
3. `supabase/migrations/202608290001_service_role_table_grants.sql`.

RLS должен оставаться включённым. Секретный серверный ключ Supabase нельзя помещать в браузерный JavaScript, GitHub, логи или архив.

## Контроль расходов

Проект рассчитан на Vercel Hobby, Supabase Free, Gemini Free Tier, Apify Free и Cloudflare Turnstile Free. Банковская карта и автоматическая оплата не подключаются. Дневной и месячный защитные лимиты останавливают новые внешние анализы до вызова Apify и Gemini; история, избранное и сохранённые результаты продолжают работать.

## Анализ безопасности

Проверены следующие меры:

- секреты хранятся только в переменных окружения Vercel и не передаются клиенту;
- сессия хранится в `HttpOnly`, `Secure`, `SameSite` cookie;
- Supabase RLS разделяет данные пользователей, а кредиты изменяются атомарными SQL-функциями;
- Origin, Cloudflare Turnstile и ограничения запросов защищают публичные точки входа;
- инструкции внутри транскрипта не должны менять системное задание Gemini;
- ответ Gemini нормализуется, а тайм-коды сверяются с сегментами Apify;
- AI-текст выводится безопасными DOM-узлами и не исполняется как HTML;
- IP используется только как HMAC-отпечаток для ограничения запросов;
- журналы не содержат паролей, ключей и полного персонального содержимого;
- ежедневная очистка удаляет устаревшие задания, ограничения, кэш и обычную историю;
- репозиторий и финальный архив проверяются на наличие ключей и локальных `.env`-файлов.

Анализ выполнен автоматическими тестами Node.js, проверкой SQL-миграций и RLS, поиском секретов по файлам проекта, а также браузерной проверкой интерфейса, консоли и сетевых сценариев на компьютере и ширине 390 px.

## Локальный запуск и тесты

Требуется Node.js 22 или новее.

```powershell
npm install
npm test
npm run dev
```

Локальная страница: `http://127.0.0.1:3000`. Полный облачный сценарий требует переменных окружения и применённых миграций Supabase.

Автоматический набор из 112 проверок охватывает регистрацию и сессии, языки, модели Gemini и fallback, кэш, лимиты, RLS, возврат кредита, структуру результата, тайм-коды, историю, экспорт, PDF, безопасность и адаптивный интерфейс.
